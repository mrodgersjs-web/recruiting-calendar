# Integration contract: Coach Contact Kit
Status: **proposal for the site lane. Nothing in this lane edits `site/`.** Consumer = site/playbook builders; producer = this folder.

## 1. What this lane provides (read-only artifacts)
| Artifact | Path | Format | Stability |
|---|---|---|---|
| Worksheets 1-5 | `deliverables/1-...md` to `5-...md` | Markdown, UTF-8 | Regenerated by `build_worksheets.py`; deterministic (tested) |
| Follow log template | `deliverables/6-follow-log.csv` | CSV, header = `contact_kit.LOG_COLUMNS` (16 cols) | Column set is the contract; add only at the end, bump `SCHEMA_VERSION` note below |
| Script templates | `contact_kit.TEMPLATES` | Python dict: `subject`, `body`, `needs[]` | Placeholders use `{name}`; `needs` lists every required field |
| Libraries | `contact_kit.py` | Python 3.9+ stdlib, no network | Functions below |
| CLI | `kit_cli.py` | argparse; exit 0 ok / 1 validation / 2 input file | See header docstring |

`SCHEMA_VERSION` = 1 (follow log). Enumerations: channel = `contact_kit.CHANNELS`; reply_type = `contact_kit.REPLY_TYPES`.

## 2. Function contracts
- `send_window(division, class_year_open_iso, today_iso, verified_on_iso=None)` -> `{division, note, family_may_write, status, days, stale_warning}`. `status` in `no_calendar_date_needed | date_missing | coaches_may_reply | coaches_may_not_reply_yet`. **The caller supplies the D1 date; this lib never invents one.** Source of dates stays `site/data.js` (system of record, per ACCESS.md 2a).
- `render_template(name, fields)` -> `{subject, body}`. Raises `MissingField` (lists blanks) or `ValueError` (promise language in user text). Output is a draft; nothing is sent.
- `check_video_link(url, minutes, title, first_30_best, tested_private_window)` -> `{ok, host, problems[], reminders[]}`. **Offline; makes no HTTP request.** A fetch-based checker is out of scope until the counsel/privacy check (DECISIONS-FOR-MIKE #4).
- `validate_log(csv_text, today_iso)` -> `{ok, errors[], rows[]}`; `due_actions(rows, today)`; `kpis(rows, window_days, today)`.
- `cadence(first_send_iso)` -> 4 reminder dates (days 0, 10, 24, 45; spacing is a hypothesis).
- `promise_hits(text)` -> list of banned phrases. **Wire into the site's copy gate (s1gate / SlopMonster) as an additional check.**

## 3. How the site lane may consume (suggested, not done here)
1. Link `deliverables/*.md` from the $15 Highlight Reel & Social playbook page as downloads (K1 attach).
2. Reuse `TEMPLATES` text in the playbook scripts section; keep `needs[]` as the form-field list.
3. A client-side port of `check_video_link` (JS) is acceptable; it must not send the URL to a server (K6 stores host + pass/fail only).
4. Send-date page reads `site/data.js`; pass its `iso_date`/`verified_on` into the same status logic. No second date table.

## 4. Hard constraints (the contract is void if violated)
- **No contact.** Nothing here emails, DMs, follows, posts, submits a questionnaire or calls. No SMTP, socket, HTTP or subprocess import in `contact_kit.py` (enforced by `test_never_fetches`).
- **No guarantees.** No copy implies access, introductions, replies or offers (K9 = 0; `promise_hits` over every deliverable).
- **No minors' data stored.** The kit collects no names, photos, video or grades; templates hold placeholders only (test: no email addresses in deliverables). Follow logs stay on the family's device.
- **No site edits** from this lane. Any wiring is done by the site owner, with Mike's exact-text approval for outward copy and the standard text gate.
- Every date shown to a family carries a `verified_on` and the NCAA source; stale > 60 days must warn.
- Disclaimer line in NOTE (`build_worksheets.NOTE`) must stay on every worksheet (tested).
